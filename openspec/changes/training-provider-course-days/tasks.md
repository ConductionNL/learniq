# Tasks: training-provider-course-days

- [x] **T1**: register: `cohort.minParticipants`, `goDecisionBy`, `dayStatus` (derived); `course.bringList[]` (plus `cohort.goDecision`, the go/no-go the derivation reads)
  - The participant's next course day shows the bring list: `EmployerBookingFacts` copies `course.bringList` onto each participant's `enrolment.bringList` with the other day facts, and the participant portal's course day collections show it under "What to bring" ("Meenemen"). Asserted in `EmployerBookingFactsTest` and `ParticipantSitePagesTest`. The public course page is portaliq's public index item, which has no list field yet, so it does not show the list.
- [x] **T2**: status derivation on every booking, enrolment, decision and date change; manual move log
  - Derivation: `CourseDayStatus` (rules), `CourseDayStatusService::restamp()`, queued by `CourseDayStatusCascade` and run by `CourseDayRestampJob`.
  - Manual move: `CourseDayStatusService::move()` (`POST /api/course-days/{id}/status`) stores `cohort.dayStatusMove` with a fingerprint of the facts; it stands until those facts change. Every move, derived change and decision is appended to `cohort.dayStatusLog`.
- [x] **T3**: go/no-go action and moving participants to another day of the course
  - `CourseDayController` (action `course-day.plan`): `decide`, `alternatives` (coming days of the course with places) and `moveParticipants` (open bookings and placed enrolments of a cancelled day). The buttons on the course day page are part of T4.
- [x] **T4**: the course days board per status (library board view) and the calendar tab
  - The Course days page (`CourseDays`, menu under Learning for coordinators and administrators) is an index over `Cohort` that opens on the library board by `dayStatus`, with a table and a calendar view. A drop runs `moveCourseDay`, which posts to `POST /api/course-days/{id}/status` (the logged manual move), never a PATCH of the status. The calendar places a day on `cohort.dayDate`, which `CourseDayStatusService::restamp()` now stamps from the day's last session.
  - The page lists every cohort: the index has no fixed filter for "has a course", so on an install that also has teaching groups they appear in the Open column.

Left: the trainer's Today card and the group with a column per part and per practical assignment (manifest pages), so the task stays open.
  - Today card built: `CourseDayPartsWidget` on the teacher dashboard (`teacher-course-day-parts`) asks the parts endpoint for each of today's sessions in the teacher's scope that has parts and, when a part has begun without attendance, says "The afternoon has begun. The board's group grid with a column per part and per practical assignment is not in the spec and is left for the roll-call page.
- [x] **T6**: the planner's Today: first-today rules, enrolments to confirm, occupancy, trainers and rooms

  - `PlannerTodayWidget` ("Course days today") is added under the admin and teacher dashboards only when that endpoint answers, so a reader without `course-day.plan` sees no card.
