# Tasks: today-first-per-school-role

- [x] **T1**: the First today rule list per role (named queries + sentence templates), and the card on Today
  - Partly built: the rule list and its named queries. `Service/Today/FirstTodayRules` holds each role's rules in the design's order (`ORDER`), maps a user to her role on Today (`roleFor()`: a teacher is the group teacher in po and the subject teacher elsewhere, `coordinator` is the intern begeleider, `administration-manager`, `team-lead` and `admin` the head; `inView()`: a teacher in the Mentor view reads the mentor's rules) and picks the first rule with a row, asking later rules only when the earlier ones found nothing (`first()`). `RegisterFacts`, `AttendanceFacts` and `FollowUpFacts` (in `Service/Today`) count each rule from rows already read; `FirstTodayReader` reads them (the register groups through `RollCallAccess`, everything else with the caller's own rights); `FirstTodayService` puts it together. `GET /api/today/first` (`TodayFirstController`, `?view=mentor` for the Mentor view) answers `{role, rule, count, ...}` with what the card names (group, lesson, round, number of parent reports), or `rule: null`. Definitions where the schemas name no exact field: a learning plan "ends" on its `nextReviewAt` and a group plan on its `periodEndDate`, and a plan still `active` has no evaluation under way; "past half the decision time" is midway between `created` and `decideBy`; "over the limit" is an unreported `langdurig-relatief-verzuim` or `thuiszitter` flag. The card on Today (decided 24 Nov 2026, under Ruben's delegation of product decisions): Today draws ONE First today card per view (`today-first-rule` in the Docent view, `mentor-first-rule` in the Mentor view), not one card per rule. It reads `GET /api/today/first` once; for a rule Today has a card for, the answer carries the card's sentence (`title`), its line (`reason`) and the page its action opens (`page`), written by `Service/Today/FirstTodayCard` with the pages in `lib/Service/Today/first-today-pages.json`. So a role only ever sees its own rule, and REQ-STD-003 holds because every page in that file is one each role of the rule already reaches (checked per role in `structureProfile.test.mjs`). The action reads "Open" (the library fills no label from the answer), not the board's per-rule label. The open-flags card stays as it was, because `appinfo/attention.json` mirrors it for LaunchPad; its kicker now reads "Attendance", so Today shows at most one card headed "First today". The placement and exam rules get no card: the simple Today is not for those roles. Tests: `FirstTodayCardTest`, `TodayFirstControllerTest`, `structureProfile.test.mjs` ("each Today view has one First today card", "Today links no page...").
