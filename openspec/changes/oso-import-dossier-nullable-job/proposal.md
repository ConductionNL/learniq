# Proposal: oso-import-dossier-nullable-job

## Summary

`OsoImportDossier.dataExchangeJobId` is required, typed `string` and described as "when it came in through one", and the demo rows hold `null`. Hydra gate 101 validates every demo row against its schema and refuses these. #1195 fixed the same mismatch on LvsResult by declaring the field nullable; this change does the same for OsoImportDossier (schema 0.2.2, register 0.31.5).

## Motivation

Follow-up from lane f-quality and TRACKER-R2 "ROUND 3 FINAL". With the mismatch, every PR that touches the register reads gate 101 red.

## Scope

### In Scope

- `dataExchangeJobId` gets `nullable: true` and says a dossier entered by hand has none. It stays required, as on LvsResult: the key is present, the value may be null.
- A register test that holds every demo null to a nullable property, so the next schema with this mismatch fails in PHPUnit and not only in the gate.
- Three demo rows each for `DossierReview`, `ExchangePartnerApproval` and `TeldatumCheck` (added by #1157 without demo data), generated by the hydra mock generator and appended, so gate 101 passes on the register as a whole.

### Out of Scope

- Any change to how a dossier is received or reviewed.

## Rollback Strategy

Revert the merge commit.
