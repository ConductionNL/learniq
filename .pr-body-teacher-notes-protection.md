## Scope

Teacher notes move out of the lesson into a staff-only `LessonTeacherNote` schema that learners and guardians cannot read on any path. Until now a note was a `teacherNote` block inside `Lesson.blocks`: the lesson player hid it, but `Lesson` is readable by every signed-in user (`authorization.read: ["authenticated"]`), so any learner who asked the objects API for a lesson read every note in full, including the speaker notes of every imported presentation.

Round 2 follow-up from learniq #1080: "teacher notes are hidden, not protected".

## What changes

- **Register** (`info.version` 0.29.2, `Lesson` 0.5.0). New `LessonTeacherNote` (slug `lesson-teacher-note`, `schema:Comment`): `lessonId`, `blockId`, `afterBlockId`, `position`, `text`, `tenant_id`. Read: instructors, team-leads, coordinators, hr, compliance-officers, administration-managers. Create, update, delete: exactly the lesson writers (instructors, hr, compliance-officers, team-leads). No `authenticated`, `learners` or `guardians` entry of any kind; not searchable. Seed row and three generated mock rows. `Lesson.blocks[].type` drops `teacherNote`, so OpenRegister refuses a lesson that still carries a note, whoever sends it.
- **Composer.** Loads the lesson's notes from the new schema and shows them inline where they were (`mergeTeacherNotes`), saves the lesson without notes (`splitTeacherNotes`, and `serialiseLessonBlocks` now drops any note block as well), then creates, updates and deletes notes by `blockId` (`diffTeacherNotes`). A failed note write says the lesson was saved but a note was not. The label now reads "Only staff can read this note. Learners and parents never see it."
- **Onboarding importer.** Slide notes go through `TeacherNoteSplitter` and are written to the note schema after the final blocks exist (the material pass rebuilds block ids), anchored to the slide's block. A lost note is reported in the import note.
- **Upgrade.** `MoveTeacherNotesOutOfLessons` (post-migration, after `InitializeSettings`): per lesson with a note, create the missing notes (matched by `lessonId` + `blockId`), and only then save the lesson without them. It never loses a note and a rerun duplicates nothing. The app `<version>` moves to `0.3.6-unstable.20260928110000` so `occ upgrade` runs it (gate 110).
- The AI assist was checked: it sends `richText` blocks only, so notes never reached a prompt.
- Notes no longer travel in course exports or store packages, which read lesson objects only.

**ADR-032 note:** this is one change that touches the register and code. The two cannot land apart: dropping the enum value without moving the composer breaks every save of a lesson with a note, and adding the schema without moving the composer and importer leaves notes readable. Recorded as a mixed-spec rationale in `design.md`.
