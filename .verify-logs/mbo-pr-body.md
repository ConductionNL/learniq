## Scope
Adds the MBO example set: one fictional college (Voorbeeldcollege Vaartveld, fictional town Vaartdam) through the 2025-2026 school year, 6175 objects in `lib/Settings/profiles/mbo.json`, generated by `scripts/example-sets/mbo.py`. It gives an MBO team the BPV, study advice and exam board schemas filled with a college that hangs together, instead of three generated placeholders per schema.

## What is in the set
- Two locations, three programmes at niveau 2, 3 and 4 (Logistiek medewerker, Verzorgende IG, Software developer), each with a kwalificatiedossier-style framework (7 kerntaken, 22 werkprocessen).
- Eight classes (one per programme and leerjaar), 250 students, one enrolment each; parents of minors as emergency contacts.
- 24 staff: a studieloopbaanbegeleider per class, BPV-docenten, a stagecoördinator, exam board chair and secretary, student counsellor, verzuimcoördinator.
- A timetable of 911 school days per class around the placement days, 792 absence marks, two attendance flags (a minor's 16 hours, an adult under 80 percent).
- 151 placements (one terminated in November and replaced) at 18 fictional leerbedrijven, 151 praktijkovereenkomsten with 453 signatures, 313 visit reports, 660 werkproces assessments.
- Unit results with resits, 834 final grades, the first-year study advice (8 flags, 8 warnings, 100 decisions: 96 positive, 2 negative, 1 negative with advice, 1 postponed), 4 exemption cases, 2 fraud cases, 7 exam accommodations.

Derived values are written the way the code writes them: final grades as `GradeAggregationEngine` and `GradePassEvaluator` compute them, PVB results as `WerkprocesGradeEmitHandler` writes them, advice credits as `BsaProgressEvaluator` counts them. `VocationalCollegeExampleSetTest` checks the final grades against the real engine classes.

## Found while building (reported, not fixed)
The set follows the code as it is. These defects surfaced while making the derived values agree, and belong to their own changes:
1. `lib/Grading/GradePassEvaluator.php` reads `passRules[].passThreshold`, but the schema declares `passRules[].minValue`, so a per-component minimum in an `all-must-pass` plan is never applied.
2. `CompetencyAttainmentRollupHandler::findCompetencyByCode()` resolves a `werkprocesCode` across every SBB framework of the tenant and takes the first hit. SBB codes like `B1-K1-W1` repeat per dossier, so a college with more than one programme links an assessment to the wrong werkproces. The set writes `competencyId` explicitly.
3. `GradeRollupHandler::recomputeFinalGrade()` writes `cohortId` into `FinalGrade`, which the schema does not declare (gate 108 territory at runtime).
4. `PokSignature.signerRole` has no value for a parent, while a minor's praktijkovereenkomst is usually co-signed by one; 198 of the 250 students are minors.
5. An exemption-only plan gets a `FinalGrade` with `passed: null`, and `BsaProgressEvaluator` counts only `passed: true`, so an exempted first-year unit earns no study advice credits. The set exempts only second- and third-year components.
