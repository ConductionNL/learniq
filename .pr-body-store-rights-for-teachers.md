## Scope

Any teacher installs a shared course from the Store as their own copy, and publishing to the Store is limited to the groups learniq's permission matrix names for `course-package.share`, by default the team leads. The Store page and the export screen now show each user the actions they may take. An administrator connects the course registry on the Learniq admin settings page instead of with `occ`.

Decision D27 (Ruben, 27 September). **Stacked on #1128** (`store-publish-through-plane`): land #1128 first.

## What changes

- **Matrix.** New action `course-store.install`, seeded `["admin", "instructors", "team-leads"]`; `StoreController::install()` requires it. `course-package.share` is seeded `["admin", "team-leads"]`. The Canvas and Moodle package upload keeps `course-package.import`, admin only. A test pins that every non-admin install group may create a Course, a Lesson and a Material, the objects an install writes as that user (coordinators are left out because the Lesson schema does not let them create lessons).
- **Existing installs, once.** `GenericInitializeActions` seeds only an empty matrix, so a new row never arrives on an existing instance. The repair step `ApplyStoreRightsDefaults` (post-migration, after `InitializeActions`) adds `course-store.install` when absent and moves `course-package.share` off exactly `["admin"]`. It reads both values from `lib/actions.seed.json`, sets the marker `store_rights_defaults_applied`, and never touches a row an administrator changed, then or later. **Assumption:** an instance whose share row still reads `["admin"]` never chose admin-only on purpose, because that was the untouched default; D27 widens it to team leads. An administrator narrows it back under Action authorization, and the step does not run again.
- **What the page shows.** `StoreAccessService::forCurrentUser()` answers `{install, publish}`, mirroring the endpoints' checks (publish needs the matrix row, an OpenRegister that can publish and the store plane's `canPublish()`). `PageController` provides it as initial state `storeAccess`, resolved lazily so an instance without OpenRegister still renders the start screen. `src/main.js` writes `canInstall` and `canPublish` into every `type: "store"` page's config; the Store page names `publishRoute: "CoursePackageExport"`. The export screen shows "Publish to the course store" only when `storeAccess.publish`, and the export menu entry now admits `team-lead`.
- **Registry connection.** New admin settings section "Course store" (`StoreRegistrySettingsSection.vue`) with registry address, register and a write-only token, backed by admin-only `GET` and `PUT /api/admin/store-registry` (`#[AuthorizedAdminSetting]`). The token is stored as a sensitive app config value, never returned (only `tokenSet`), kept when a save omits it, removed on `clearToken`. The address must be empty or an absolute http(s) URL without credentials; the register a lowercase slug. The same `occ` keys keep working.
- Copy in English and Dutch (16 new catalogue keys, `l10n/nl.js` rebuilt); admin and teacher guides updated.
